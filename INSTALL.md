# Установка и обновление дизайн-скиллов через Codex

Выполняй инструкцию в локальном чате Codex в настольном приложении. Используй публичный репозиторий, ссылку на который дал пользователь. Установка из релиза работает по HTTPS без Git. Для работы с файлами и настройками за пределами доступной области используй штатный запрос разрешений Codex.

## Определи выпуск

1. Открой последний стабильный выпуск репозитория через GitHub Releases. Возьми вложение `design-skills.zip` из опубликованного релиза. При отсутствии релиза или вложения сообщи, что команда ещё не опубликовала пакет.
2. Ожидаемая структура вложения — `manifest.json` и `skills/<имя>/SKILL.md` с остальными файлами каждого скилла. В манифесте `release` совпадает с тегом GitHub. Массив `skills` содержит `name`, `version`, `dependencies` и короткое описание изменения `summary` для каждого скилла. Идентификаторы известных зависимостей — `higgsfield` и `figma-bridge`.
3. До записи распакуй архив во временную папку, проверь пути внутри архива и наличие файлов из манифеста. Каждая папка и поле `name` в её `SKILL.md` должны совпадать с именем скилла в манифесте. Переноси целую папку скилла, включая ссылки на локальные ресурсы. В связке релизов используй только вложения исходного репозитория.

## Установи или обнови

- Для пользовательской установки в Codex копируй папки скиллов в `~/.agents/skills/`. Сохраняй данные установки в отдельном файле `~/.agents/design-skills-state.json`: URL репозитория, последний обработанный тег, имена и версии установленных из него скиллов. Записывай версию после успешного переноса файлов.
- По запросу **«проверь обновления»** сравни манифест релиза с записью об установке и покажи новые и изменённые скиллы. Файлы и настройки пользователя при проверке не меняй.
- По запросу **«обнови»** добавь новые скиллы и замени целиком управляемые папки с изменившейся версией. Перед заменой сохрани резервную копию прежней папки вне каталога обнаружения скиллов. При сбое восстанови её и явно укажи, какой скилл остался на прежней версии.
- Если имя уже занято папкой, которой эта подборка не управляет, сообщи о конфликте и спроси, что с ней сделать. При исчезновении скилла из манифеста сообщи об этом и оставь установленную копию. Используй только источник, зафиксированный при установке, если пользователь явно не попросил его заменить.

## Подключи зависимости

Проверь зависимости скиллов из манифеста. Если они уже работают, используй существующие подключения. Если новое подключение требует входа или действия в приложении, дай конкретный следующий шаг и сообщи статус остальных компонентов.

- **Higgsfield MCP.** Используй официальное подключение Higgsfield. Для удалённого MCP официальный адрес — `https://mcp.higgsfield.ai/mcp`. Пользователь входит в свой аккаунт и подтверждает OAuth. Для проверки достаточно запроса модели или списка моделей. [Официальная инструкция Higgsfield](https://higgsfield.ai/creator-hub/help-center/integrations/how-do-i-connect-higgsfield-to-ai-agent)
- **Figma MCP Bridge.** Проверь доступность Node.js и `npx` в среде запуска Codex. Если их нет, помоги установить Node.js из [официального источника](https://nodejs.org/en/download). Настрой локальный сервер с командой `npx` и аргументами `-y @gethopp/figma-mcp-bridge` по инструкции проекта. Помоги скачать плагин из релиза. Пользователь в Figma Desktop выбирает **Plugins → Development → Import plugin from manifest**, указывает `plugin/manifest.json` и запускает Bridge в рабочем файле. После запуска проверь доступ через `list_files`. [Инструкция Figma MCP Bridge](https://github.com/gethopp/figma-mcp-bridge#quick-start)

## Сообщи результат

Для установки перечисли доступные скиллы и действия, которые ещё нужны для подключения. Предложи открыть новый локальный чат. Для проверки или обновления дай одну строку на категорию: **«Новое»**, **«Обновлено»** и, при необходимости, **«Требуется действие»**. Бери формулировки из манифеста или журнала изменений. Если пользователь пропустил несколько выпусков, учитывай записи между установленным и текущим тегами, когда они доступны.
