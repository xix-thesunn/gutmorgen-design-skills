# GM Design Skills

Для установки скопируй этот текст в новый локальный чат Codex:

> Установи набор GM Design Skills из https://github.com/xix-thesunn/gutmorgen-design-skills. Прочитай README репозитория и следуй инструкции для агента. Покажи версию и патчноут и дождись моего подтверждения.

После установки начни новый чат. Для работы с товарными карточками GUTEN MORGEN используй `$do-product-page`, для проверки обновлений — `$gutmorgen-update`.

## Инструкция для агента

1. Прочитай [инструкцию установки и обновления](plugins/design-skills/skills/gutmorgen-update/SKILL.md) из этого репозитория. При первой установке следуй ей напрямую, даже если скилл ещё недоступен в чате.
2. Проверь состояние пакета через `codex plugin list --marketplace gutmorgen --json`. Пустой список используй как внутренний сигнал для первой установки. Покажи предлагаемую версию, патчноут и состав пакета и дождись одного подтверждения.
3. После подтверждения подключи источник командой `codex plugin marketplace add https://github.com/xix-thesunn/gutmorgen-design-skills.git`, если он ещё отсутствует. Если правильный источник уже добавлен, обнови его через `codex plugin marketplace upgrade gutmorgen`. Для первой установки затем выполни `codex plugin add design-skills@gutmorgen`.
4. Проверь результат. Если установка прошла успешно, попроси пользователя начать новый чат и при необходимости назови нужный скилл. Если команда установки завершилась успешно, но итоговый список пуст, попроси начать новый чат и проверить доступность скиллов. При явной ошибке установки кратко объясни причину и следующий шаг.
5. В ответах пользователю опускай служебные команды, сырые выводы и пустые списки. Из команд показывай только вызовы скиллов, например `$do-product-page` и `$gutmorgen-update`.

## Название релизов

На GitHub используй заголовок `GM Design Skills vX.Y.Z` и тег `vX.Y.Z`. Патчноут публикуй в описании релиза.

## Подготовка Figma MCP Bridge на Windows

Когда пользователь просит настроить Bridge, агент запускает `scripts/prepare-figma-bridge.ps1` из клона этого репозитория в локальной сессии Windows. Скрипт проверяет контрольную сумму официального архива gethopp и выводит абсолютный путь к `manifest.json`. Плагин сохраняется в системной папке «Документы», включая случай перенаправления в OneDrive, в подпапке `Figma MCP Bridge/v0.0.27`.

Агент проверяет `codex mcp get figma-bridge` и переиспользует рабочую настройку. Если записи нет и Node.js 20 или новее и npm доступны, регистрирует сервер соответствующей версии:

```powershell
codex mcp add figma-bridge -- cmd.exe /d /c npx -y @gethopp/figma-mcp-bridge@0.0.27
```

Если доступен интерфейс Figma Desktop, агент импортирует подготовленный манифест через меню `Plugins → Development → Import plugin from manifest` и запускает Bridge в указанном файле.

Если интерфейс недоступен или импорт не удалось завершить, агент сообщает, какие шаги выполнены, и показывает **абсолютный путь, возвращённый скриптом**, с короткой инструкцией:

1. Открой нужный файл в Figma Desktop.
2. Выбери `Plugins → Development → Import plugin from manifest` и укажи путь к `manifest.json` из ответа агента.
3. Запусти Figma MCP Bridge в этом файле.

После запуска в новой сессии Codex вызови `list_files` и проверь, что Bridge видит нужный файл. Если сервер не зарегистрирован, агент отдельно сообщает причину.

## Статус проверки

Установка набора из GitHub проверена на Windows для версии 0.1.0. Подготовка Bridge в версии 0.1.1 требует проверки в локальной Windows-сессии. Автоматическая установка Node.js, Higgsfield MCP и Portable Git в эту версию не входит.
